你开着 VPN，打开一个“查 IP”的网站，显示的是日本。看起来一切正常。可同一时间，你家宽带运营商的服务器上，可能正记录着你刚刚查询过的每一个网址。

这种情况叫 DNS 泄漏。它不影响你上网，所以大多数人从来没发现过。

## 先说 DNS 是什么

电脑之间通信靠的是 IP 地址，一串数字。人记不住数字，所以有了域名，比如 `example.com`。把域名翻译成 IP 地址的服务，就是 DNS。

你每打开一个网站，设备都会先问一次 DNS：这个域名对应哪个 IP？这一步非常快，快到你感觉不到，但它会留下一条记录：**某个时间，某台设备，查了某个域名。**

默认情况下，替你回答这个问题的是宽带运营商或者手机运营商的 DNS 服务器。也就是说，即使网站本身用的是 HTTPS 加密，运营商仍然可以通过 DNS 查询知道你去了哪些网站。

## 泄漏是怎么发生的

正常工作的 VPN，会把 DNS 查询也放进加密隧道，交给 VPN 服务商自己的 DNS 服务器来回答。这样运营商只能看到你在和 VPN 服务器通信。

泄漏，就是有一部分 DNS 查询绕开了隧道，还在发给运营商。常见的原因有这么几种。

**系统设置抢了先。** Windows 会同时向多个网络接口发 DNS 查询，谁先回答就用谁的。如果本地网卡的 DNS 回答得更快，查询就“漏”了出去。

**手动改过 DNS。** 有些人为了速度，在路由器或系统里把 DNS 改成了公共 DNS。VPN 如果没有强制接管，这些设置可能继续生效。

**VPN 断线的那几秒。** 隧道断开、重新连接之间，如果系统没有拦截，查询会直接走普通网络。很多 VPN 提供的“断线保护”（Kill Switch）就是为了堵住这几秒。

**App 自带的 DNS。** 一些浏览器开启了“安全 DNS”（DNS over HTTPS），会直接连接自己设定的服务器，不一定经过 VPN 的规则。

## 两分钟自己测一测

测试方法很简单，不需要装任何东西。

先在不开 VPN 的情况下，打开一个 DNS 泄漏检测网站，比如 dnsleaktest.com 或 browserleaks.com 的 DNS 页面，运行“扩展测试”。记下结果里出现的 DNS 服务器，通常会是你本地运营商的名字。

然后打开 VPN，刷新页面，再测一次。

如果第二次的结果里只出现 VPN 服务商的服务器，或者与你所连节点同一地区、你认不出但也不是本地运营商的服务器，说明没有泄漏。如果仍然出现了你本地运营商的名字，那就是泄漏了。

:::tip
测试时最好关掉其他正在联网的程序，并且多测两三次。偶尔一次结果异常，可能只是缓存，连续出现才值得处理。
:::

## 另外两种容易被忽略的泄漏

DNS 不是唯一会“漏”的地方。下面这两种，同样可以在上面那两个网站上测出来。

**WebRTC 泄漏。** WebRTC 是浏览器里用于视频通话、文件传输的技术。为了让两台设备直接连上，它会尝试获取你的真实 IP，有时就绕过了 VPN。浏览器测试页面如果在“WebRTC”一栏显示了你的真实 IP，就说明有这个问题。Firefox 可以在高级设置里关掉它；Chrome 系浏览器通常需要装一个可信的扩展来限制。

**IPv6 泄漏。** 现在很多宽带同时分配 IPv4 和 IPv6 地址。如果 VPN 只接管了 IPv4，访问支持 IPv6 的网站时，流量就可能直接走 IPv6 出去，暴露真实地址。好的 VPN 会同时处理 IPv6，或者在连接时临时屏蔽它。

## 发现泄漏之后怎么办

按影响从小到大，可以依次尝试。

在 VPN App 里找一找“DNS 保护”“防泄漏”“断线保护”之类的开关，打开它们。很多泄漏问题这一步就解决了。

检查系统和路由器里有没有手动设置过 DNS。如果有，先恢复成自动获取，再测一次。

浏览器里的“安全 DNS”功能，在使用 VPN 时可以先关掉，或者改成跟随系统设置。

处理 WebRTC 和 IPv6，按上一节的方法来。

如果以上都做了还在泄漏，问题多半出在 VPN 本身。联系客服时把测试结果截图发过去，能省很多来回沟通的时间。

## 为什么值得花这两分钟

DNS 查询记录拼起来，就是一份完整的上网清单：你几点看了新闻、常去哪个论坛、最近在搜什么病。单独一条无关紧要，长期积累就不一样了。

用 VPN 的目的之一，就是不让这份清单落在不该看到它的人手里。花两分钟测一次，确认它真的在按你以为的方式工作，是值得的。
